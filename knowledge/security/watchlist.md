## Version traps

- A patch level can carry the fix for one CVE while still being exposed to a newer out-of-band hotfix (Magento `2.4.7-p10` requires VULN-39341 for StyleSmuggler).
- The latest patch of a branch is not proof of safety — verify against the specific advisory, not the version string alone.
- Distribution-level security patches (e.g. Linux distro backports) do not map cleanly to upstream version ranges. Check the distro advisory too.
- A plugin's `readme.txt` Stable tag can lag the shipped code. The authoritative version is the plugin's own asset URL (`?ver=`) and the banner inside its minified JS — cross-check both before mapping a CVE.
- A bundled dependency's version string (e.g. `royal-elementor-addons/assets/js/lib/particles/particles.js?ver=3.0.6`) is not the plugin's version. Attributing it as the plugin version produces a false match.
- The fix version can sit immediately above the affected ceiling (Elementor Pro 3.30.0 vs fix 4.2.2; Royal Addons 1.7.1065 vs fix 1.7.1066). Read the patch level, not the major.
- **nginx 1.30.2 is the fix, not the flaw.** It closes CVE-2026-9256; 1.30.1 closed the earlier `ngx_http_rewrite_module` overflow. A banner showing the fixed version is not a vulnerable one.
- **FortiOS: patching is not recovery.** CVE-2025-68686 abuses a symlink planted by an earlier compromise. The fix removes the symlink but does not un-disclose what was already read — rotate all secrets on any previously exposed SSL-VPN.
- **Cite CISA KEV for exploitation status, not the vendor field.** Fortinet's advisory for CVE-2025-68686 shows `Known Exploited: No` while KEV lists it (2026-07-27). A stale vendor field does not override KEV.
- **SAP Commerce Cloud branch families are distinct.** HY_COM 2205, COM_CLOUD 2211 and 2211-JDK21 are separate affected branches; one CVE can cover all three, so confirm the branch, not the "latest" label.
- **SoftExpert "Suite" is not automatically "SE Excellence Suite".** CVE-2023-30330 affects SE Excellence Suite 2.x before 2.1.3 — confirm the product line and version before mapping.
- **An NVD CPE version query over-includes; filter by the vendor affected range.** `cpe:2.3:a:grafana:grafana:9.5.1` returned 25 CVEs, but only 19 include `9.5.1` in `affected[].versions[]`. Test `version <= target < lessThan` per entry; drop entries whose earliest affected version is above the target (here six CVEs are ≥10/11). A CPE match is not an attribution.
- **Intel EMA: 1.14.5 is the fix, not the flaw.** CVE-2025-35990 affects EMA before 1.14.5, so a host showing `EMAVersion '1.14.5.0'` is patched. A host on 1.12.2.0 is affected by CVE-2025-35990 and by CVE-2024-32483 (fix 1.13.1.0) at the same time — check both ranges.

## Platform notes

- **Headless Magento / PWA**: depends on GraphQL, so the StyleSmuggler interim mitigation (disable GraphQL) is usually unavailable — treat as higher exposure.
- **Magento hosting (`*.magehub.com.br`, Magehub/Mageshop)**: multi-tenant Magento; a compromise can threaten neighbours → supply-chain relevance.
- **WordPress 7.1**: changed how hook callback IDs are built (string → int under some conditions); caching plugins that call `substr()` on them (WP Rocket < 3.23.2.2, fixed 2026-08-20) throw a fatal error. Treat a core-major jump as an availability review, not only a CVE review.
- **WordPress MCP adapter**: the `mcp` REST namespace exposes `POST/GET/DELETE /mcp/mcp-adapter-default-server` and `/mcp/mcp-oauth-server` — an agent/tool-execution surface to inventory separately from content APIs.
- **Evolution API ≥ 2.4.0**: requires license activation; an unlicensed deployment returns `503 LICENSE_REQUIRED` on business routes (license/manager/health stay public).
- **Remote-access portals (Check Point / FortiGate): an internet-exposed portal is `alto` on exposure alone; the product banner proves the product, never the patch level.** `Server: CPWS` is Check Point Web Server (Check Point Mobile Access / Remote Access VPN), **not** FortiGate — FortiGate SSL-VPN serves `/remote/login`. Confirm the build through an authenticated read before mapping any CVE, and read the response body (product label + copyright) to settle the product identity when a `Server` header is ambiguous.
- **Citrix NetScaler**: the CitrixBleed class applies only when the appliance is configured as a Gateway (VPN/ICA/CVPN/RDP) or AAA vserver. Patching does not invalidate stolen session tokens — rotate them.
- **Apache Tomcat default banner**: `Apache-Coyote/1.1` is the default HTTP connector server string across supported Tomcat versions. It identifies the product, not the version — never map a CVE from it.
- **Strapi admin at `/admin`**: the version is not exposed on the login page. Correlate only after an authenticated read; do not infer the Strapi major from the URL shape.
- **Chef Infra Server**: the `/version` endpoint is unauthenticated and returns the exact server version plus a component inventory (with version GUIDs). The branch 12 line ended security support on 2020-12-31 (EOL). An internet-exposed Chef Infra Server is high exposure — it stores all node data and the credentials that drive the managed fleet. Name the product, the exact version and the EOL; never force a CVE without a matching advisory range.
- **Cloudflare Access (Zero Trust) redirect**: a `302` to `<org>.cloudflareaccess.com/cdn-cgi/access/login/<host>?kid=…&meta=<signed-JWT>` is an access control, not a finding. The `meta` JWT carries `hostname`, `aud`, `auth_status` and `real_country`. Redact the JWT, the `kid` query value and the `CF_AppSession` cookie from stored evidence.
- **WordPress.com dangling custom domain**: A records to `192.0.78.x` (Automattic), a TLS certificate `CN=wordpress.com` without a SAN for the host, and a `403` body carrying `Active domain connection for this domain not found` together mean the custom domain is no longer connected at WordPress.com while DNS still points there — a subdomain-takeover candidate.
- **A wildcard certificate for a tenant label removes the tenant-name disclosure in CT**; without it, per-tenant certificates (`<customer>.workspaces.<domain>`) publish the customer list. Rate the disclosure as business confidentiality (`info`).
- **White-label / multi-tenant residue (live asset, not archive).** A legacy app that still serves another tenant's brand assets (`.brandX*` classes, `cdn-brandX.<vendor>.tld` URLs, a `.plataforma-<vendor>-logo` class) and a template variable (`dominioWeb="<other-brand>.tld"`) confirms a shared platform whose configuration was not cleaned per tenant. Confirm from the live asset where possible; treat tenant isolation and cross-tenant data as unconfirmed until an authorized test. Rate as identity/tenant-governance hardening (`baixo`); the platform vendor stays OSINT-only.
- **An internet-exposed Grafana is `médio` on exposure + EOL version, not `alto` without a confirmed condition.** The exact version is unauthenticated at `GET /api/health` (`{"version":"X.Y.Z"}`); `/api/search` and `/api/user` returning `401` prove anonymous access is disabled. Read `/api/health`, then check the exact NVD range before citing a CVE — `9.5.1` sits in `CVE-2023-3128`'s `<9.5.4`, but that flaw requires Azure AD OAuth with a multi-tenant app, a condition not observable from outside. Rate `médio` (exposure + EOL + range) and name the unconfirmed condition; do not jump to `alto`/`crítico` on the CVSS alone.
- **Read `edition` from `/metrics`, not from `/api/health`.** `/api/health` gives the version but not the edition; `grafana_build_info{edition="enterprise",version="X.Y.Z"}` in the (often unauthenticated) `/metrics` response settles OSS vs Enterprise. The edition changes the CVE set — `CVE-2023-4399` affects Enterprise only. An open `/metrics` is itself a `baixo` finding (edition, exact version, internal API handler inventory, feature toggles, alerting/DB metrics — no PII). `/signup` returning the SPA shell is not proof that self-registration is enabled; only a `POST` (state-changing) or `/api/frontend/settings` settles it.
- **WordPress user enumeration has a second vector besides the REST route.** Even with `/wp-json/wp/v2/users` hardened, `GET /wp-sitemap-users-1.xml` (WP core sitemaps) lists every author archive (`/author/<slug>/`) unauthenticated — the same logins, delivered to search engines. Check both vectors together; they share one remediation.
- **A WordPress REST index is a stack inventory.** `GET /wp-json/` returns the full route table and every plugin namespace (`elementor/v1`, `betterlinks/v1`, `litespeed/v1`, `pys-*`, `hostinger-*`). It is normal WordPress behavior, but it hands the plugin stack to an unauthenticated observer — rate `info` and use it to drive version fingerprinting via each plugin's `?ver=` asset.
- **A Rails/Devise member portal exposes its access model at `/users/sign_up`.** A login page with no signup link is not proof registration is off. Probe `GET /users/sign_up`: a `404` rendered with the platform's own error page proves Devise `registerable` is disabled (invite/admin provisioning only); a `200` form would prove public self-registration. The password reset lives at `/users/password/new`. Do not create an account or submit credentials on a vendor-hosted tenant without separate vendor authorization.
- **A client tenant on a vendor SaaS is testable only through the client's own subdomain.** When the portal CNAMEs to the vendor (`<tenant>.<vendor>.tld`), a read-only `GET` via the client's subdomain observes the client's tenant; creating accounts or submitting credentials there writes to the vendor's shared platform and is out of bounds unless the vendor separately authorizes. Record the distinction explicitly.
